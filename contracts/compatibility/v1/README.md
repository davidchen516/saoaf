# 兼容性矩阵与 N/N-1 消费者夹具

## 机制

`<version>/consumer-fixtures/` 是**钉在该版本上的消费者样例**。contractlint validate
对这些夹具执行双重断言：

1. **对钉定版本**：夹具通过该版本 schema（发布时保证）。
2. **对当前最新版本（N）**：旧版本消费者夹具必须继续通过当前 schema——
   即向后兼容的机器证明。破坏这一点的变更会被 breaking-change 门禁拦下，
   只能走新 major（新目录 `vN+1/`，旧版本目录保留不删）。

## 当前矩阵

| 发布版本 | 消费者夹具数 | 对当前版本（v1）验证 |
|---|---|---|
| v1 | 2 | PASS（contractlint validate 输出含 consumer-fixtures 计数） |

## 演进规则

- 向后兼容变更（新增可选字段/枚举值/操作）→ 编辑 `v1/`，夹具继续全绿。
- 破坏性变更 → 新建 `v2/` 目录并迁移；`v1/` 契约与夹具原样保留（历史不删除），
  v1 消费者夹具仍对 v1 schema 验证，v2 schema 验证时标注兼容性声明。
